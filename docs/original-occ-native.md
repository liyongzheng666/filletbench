# Original OCC manual-review series: fresh native controls

This track reruns the native operations from the original manual-review series. It does not derive requests from the later 104 ordinary paired jobs. The source records, original model revisions, original finite edge geometry, original radius sets and current manual variant IDs are frozen in `adapters/occt/original/requests.json` and `data/original-occ/`.

## Execution and evidence

Run from the repository root in a Python environment with `cadquery-ocp==7.9.3.1.1`, using OCCT 7.9.3:

```sh
python -m pip install -r adapters/occt/requirements.txt
python adapters/occt/original/run.py --case 22 --timeout 60
python adapters/occt/original/run.py --timeout 60
python adapters/occt/original/audit.py
```

`--job` selects one original request. `--output` changes the run root. The runner launches a bounded subprocess per request. No FreeCAD executable, SDK directory or local virtual environment is required or embedded. The optional extraction utility `freeze_requests.py --workspace <original-review-workspace>` is only for freezing private historical metadata; normal reproduction needs only repository fixtures.

Every request binds the full source BREP SHA-256, the historical operation BREP SHA-256 when available, complete world-space edge samples, length, endpoint coverage, support adjacency and effective native call parameters. Runtime edge indices are diagnostic output. Selection must resolve to exactly one complete finite native edge; an ambiguous selection stops before the kernel call.

The current track reads the frozen base model, extracts the original named compound child or performs an explicit portable preprocessing recipe, then independently compares the operation input against its frozen historical counterpart. Comparison includes topology counts, all edge lengths, area, volume and optimal bounding box; target geometry is separately checked by finite native curve projection. `before.brep` and `before.mesh.json` are generated by this execution, and their actual operation input hash is recorded separately from historical serialization hashes.

Portable recipes include sewing original finite walls, the boss skin / floor-footprint Boolean subtraction, positive-quadrant clipping, the original case36 support-plane extension and finite band, and current part extraction for rebuilt case31. No prepared input read is called `from_base`.

For case24, the second operation is selected on the actual first result using the two original analytic support planes, the original finite root line and collinearity. It does not reuse a numeric edge index from the first input. For cases33 and34, each radius is bound to an explicit physical endpoint, then to the actual contour endpoints before `SetRadius`; constant-radius substitution is forbidden. Case35's internal C2 control calls `SetContinuity(GeomAbs_C2, 1e-4)` but does not certify G2 joins or a softness parameter.

## Separate validation gates

The summary keeps these facts separate:

1. `native_call_executed`, native `Build` completion and contour diagnostics.
2. Native BRepCheck and BOP argument analysis, including self-interference and curve-on-surface checks.
3. BREP readback, area change and solid-count preservation.
4. STEP transfer/write/read, mass/topology checks and an independent native/BOP check of the readback shape.
5. Source special semantics, whole-shape correspondence, continuity and human appearance acceptance, which this native runner does not certify.

STEP configuration is initialized through `STEPControl_Controller.Init_s()` before applying `write.surfacecurve.mode=1`, `write.precision.mode=0` and `read.surfacecurve.mode=0`. Both setter return values and effective values are checked and recorded. The superseded first configuration diagnostic is explicitly marked and is not a request-equivalent result.

An `IsDone` candidate is preserved as `result.brep` and `result.mesh.json` even if a later native or STEP quality gate fails. An available partial native result is retained separately. Meshes use the repository schema `{vertices, triangles, face_ids, edges, selected_edges}`. No old result or screenshot is used as fresh kernel output.

`native_and_step_passed` means only the listed native and exchange gates passed. It does not mean that the original advanced Parasolid option was used, an explicit composition was replaced, a complete radius law was proved, G2 was proved or the appearance was accepted. The original manual compositions remain separate variants.

## Revision boundaries

The old batch base path has changed for cases24,31,33 and34. Their old batch controls are isolated under `historical_batch_native`, with `source_revision_mismatch` and `frozen_prepared_input_replay`. These 15 requests operate on the actual frozen old `before.brep`; their missing historical base revision and preprocessing recipe gap remain explicit. They are not the default current model.

The current controls instead use the corrected case24 oblique base and two native operation orders, the rebuilt case31 A body with R6/R7, the same fitted case33 shell and physical two-end radii, and the same current case34 convex solid and two-end radii. The preserved case31 blade-only input is not executed as a native fillet request.

Case22 R6 is a concrete evidence boundary: the original history reports a valid native candidate followed by a STEP BOP `InvalidCurveOnSurface` failure. The fresh run preserves that history, generates a new candidate from the base and records the current native and STEP gates independently. A native valid flag cannot erase the historical failure or imply all exchange gates passed.

## Machine-readable outputs

- `runs/original-occ-native/index.json`: `rows` / `entries` contain original case number, original variant ID, operation label, track, source revision, repository-relative summary and run directory, outcome and artifacts.
- `runs/original-occ-native/<job_id>/summary.json`: actual request, selection, effective parameters, preprocessing classification, historical gates and fresh gates.
- `runs/original-occ-native/audit.json`: independent coverage, SHA binding, effective parameter, physical endpoint, selection and mesh checks.

The independent audit verifies execution integrity, including failed kernel calls. A clean audit does not turn a failed geometry or STEP gate into a pass.

Notable fresh observations:

- Case22 R6/R3/R10: native and BREP checks pass; STEP readback is BRepCheck-valid but reports two `BOPAlgo_InvalidCurveOnSurface` faults. Mass/topology checks alone pass and therefore do not conceal that exchange failure.

- Current case35 default and requested internal-C2 circle controls pass the listed native and STEP gates. No fresh curvature/G2 acceptance or softness capability is claimed.
